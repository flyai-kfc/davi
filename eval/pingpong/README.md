# eval/pingpong — 핑퐁 eval

**핑퐁**(목표 구체화) 단계만 떼어, 발화 대신 텍스트로 성능을 재는 하니스(#329).
화면 fixture 회귀를 보는 `../`의 하니스와는 대상도 실행 경로도 다르다 — 공통 규칙은 `../CLAUDE.md`.

```
[사용자 LLM]  ──발화/선택 응답──▶  [어댑터]  ──▶  핑퐁 (davi 서버)
     ▲                                             │
     └──────── 질문 + 선택지 ◀──────────────────────┘
                        │  대화가 끝나면
                        ▼
                  [평가자 LLM] ── 도달·진행도·위반
```

이 폴더가 만드는 것은 **사용자 LLM과 평가자 LLM**이다. 핑퐁 자체는 남의 코드이고,
`pingpong_eval/sut.py` 어댑터 한 겹으로만 닿는다. 핑퐁이 여러 왕복에서 한 번에 선택지를 주는
형식으로 바뀌어도 **그 파일만 고친다** — 시나리오·채점·사용자 LLM은 형식을 모른다.

## 준비

```bash
python3 -m pip install -r requirements.txt
cp .env.example .env   # GEMINI_API_KEY(사용자), ANTHROPIC_API_KEY(평가자)
```

핑퐁은 davi 서버를 로컬에서 띄워서 쓴다. **스텁으로 띄우면 채점이 무의미하다.**

```bash
cd ../../server && DAVI_USE_STUB_LLM=false uvicorn app.main:app --no-access-log --log-config app/logging.json
```

## 실행

```bash
python3 -m pingpong_eval check
```
```bash
python3 -m pingpong_eval run --davi-repo ../..
```
```bash
python3 -m pingpong_eval run --only h07,h08 --no-judge
```

산출물은 `runs/<타임스탬프>/`(gitignore)에 `report.md` · `summary.json` · `transcripts.jsonl` · `meta.json`.
`meta.json`에 davi git sha와 두 모델 id가 박히므로, 프롬프트를 고친 뒤 같은 시나리오 파일로
다시 돌리면 A/B가 된다.

**수치는 `../../docs/voice-goal.md` §8에 한 줄로 남긴다** — `runs/`는 gitignore라
거기 두면 사라진다. 상세는 `BASELINE.md`.

## 시나리오

`scenarios/handwritten-30.json` — 팀이 손으로 쓴 정답 문장 30개(쉬움·중간·어려움 각 10).
`slots`가 **진행도의 분모**다. 슬롯을 더 잘게 쪼개면 점수가 올라간 것처럼 보이므로,
분해를 바꿀 때는 그 전 실행과 수치를 비교하지 않는다.

`노출`이 슬롯의 성격을 가른다.

| 값 | 뜻 | 채점 |
|---|---|---|
| `처음` | 사용자가 말해 줄 수 있다 | 목표 문장에 들어가야 정확 |
| `되물음` | 제대로 물어야 정확한 값이 나온다 (h07 "딸 집" → 인천 서구) | 되묻지 않고 넘기면 누락 |
| `미상` | 사용자도 모른다 (h08 약 이름) | **지어내면 틀림, 비워 두면 정확** |

## 측정하는 것

- **도달** — 최종 goal이 정답을 담았는가 (충족/부분/실패) + 슬롯별 정확/부분/누락/틀림
- **속도** — 라운드 수, 상한 도달률, 핑퐁 응답 지연. 세는 일은 코드가 한다(`metrics.py`).
- **위반** — 불필요 질문 · 고유명 환각 · 질문 반복 · 한번에 두개 · 선택 강요 · 앱 전문용어 · 기타 없음

`불필요_질문`은 **정답 목표에 없는 조각을 요구한 것**이다. 2026-08-21 기준선에서 실패의
근본 원인이 이것이었고, 그때는 축이 없어 증상인 `질문_반복`으로만 잡혔다.

수치는 깨끗한 손작성 시나리오 기준의 **낙관적 상한**이다. 실기기 발화의 인식 오류와
중언부언은 여기 없다.

## 유출 통제

사용자 LLM이 정답을 통째로 뱉으면 핑퐁이 1라운드에 끝나 아무것도 측정되지 않는다.
그래서 **무엇을 숨길지는 코드가 정하고**(`user_sim.py`의 난이도별 예산), LLM은 남은 것을
자연스러운 말로 바꾸기만 한다. 그 뒤 문자열 검사로 유출을 확인하고, 새면 한 번 다시 시킨다.
