## 짧은 요약 (먼저 읽어 주세요)

davi는 화면 위에 「여기를 누르세요」를 표시해 드리는 앱입니다. 그러려면 **지금 보고 계신
화면에 무엇이 있는지**를 읽어야 합니다.

- 화면에서 읽은 글자 중 **휴대폰 번호·계좌번호·주민등록번호·카드번호·이메일·기기 주소는
  기기 안에서 `•••`로 바꾼 뒤**에 보냅니다. 원래 값은 휴대폰 밖으로 나가지 않습니다.
- **다만 사람 이름, 대화방 이름, 기기 이름은 지우지 못합니다.** 화면에 있는 앱 이름과
  구분할 방법이 없어서, 이름을 지우면 「카카오톡을 누르세요」 같은 안내를 아예 만들 수
  없기 때문입니다. 그런 이름은 **가려지지 않은 채 서버와 인공지능 모델로 갑니다.**
- 사진첩·연락처·문자·통화기록·위치를 **앱이 직접 열어 가져오지는 않습니다.** 그런 권한을
  아예 갖고 있지 않습니다.
- **다만 안내를 받는 동안 화면에 보이는 것은 읽습니다.** 문자 앱을 안내해 드리는 중이라면
  그 화면에 떠 있는 대화 내용이, 연락처 화면이라면 거기 보이는 이름이 위와 같은 방식으로
  서버에 갑니다. **「권한이 없다」와 「화면으로는 나가지 않는다」는 다른 이야기입니다.**
- 목소리로 목표를 말씀하시면 **글자로 바뀐 문장만** 서버로 갑니다. 녹음된 소리 자체는
  davi 서버가 받지도 저장하지도 않습니다.
- 검색어·메모처럼 입력칸에 적으신 값도 화면 정보로 읽습니다. 위 개인정보 패턴은 먼저
  가리고, **비밀번호 칸과 인증·보안 코드라고 표시된 칸의 값은 읽지 않습니다.**
- 현재 인공지능 제공자는 **OpenAI**입니다. 다비 서버가 원문을 저장하지 않는 것과 달리,
  OpenAI에는 응답 데이터와 악용 방지 기록이 보관될 수 있습니다. 기간과 예외는 §6·§7에 적었습니다.

## 2. 이 방침이 적용되는 범위

davi Android 앱과 davi 추론 서버(`/v1/*`)에 적용된다. 앱이 안내하는 **다른 앱**(카카오톡·
설정 등)의 개인정보 처리에는 적용되지 않는다 — 그 앱들의 방침은 각 앱 제공자가 정한다.

## 3. 수집·처리하는 항목

### 3-1. 화면 정보 (필수)

안드로이드 **접근성 서비스**로 현재 화면의 요소 목록을 읽는다. 안내를 시작한 뒤,
화면이 바뀔 때마다 읽는다.

읽는 것 — 요소의 **이름(label)과 입력칸의 현재 값**, 역할, 화면 위 위치(좌표), 누를 수
있는지·켜져 있는지·가려져 있는지 같은 상태값, 창 제목, 스크롤 가능 여부, 키보드가 떠 있는지,
목록의 몇 쪽인지,
현재 앱의 패키지명, 그리고 화면이 실제로 바뀌었는지 판정하기 위한 **화면 내용의 해시값**
(원문 글자가 아니라, 기기 안에만 있는 무작위 값을 섞어 만든 지문이다 — 서버는 이 값으로
원문을 되돌릴 수 없다).

**화면 요소 목록의 항목은 `server/app/schemas.py`의 `UiElement`·`Screen`이 전부다.** 같은
요청 봉투에는 그 밖에 목표 문장(§3-2)·안내 이력(§3-3)·**앱 버전**이 함께 실린다.

**기기에서 먼저 가리는 것**(`app-android/.../PrivacyMasker.kt`, 서버 `masking.py`가 같은
규칙으로 한 번 더 검사한다):

| 가리는 것 | 예 |
|---|---|
| 이메일 주소 | `hong@example.com` → `•••` |
| 휴대폰 번호 | `010-1234-5678` → `•••` |
| 주민등록번호 | `900101-1234567` → `•••` |
| 카드번호 | `1234-5678-9012-3456` → `•••` |
| 계좌번호 형태의 숫자열 | `123-456-789012` → `•••` |
| 기기 MAC 주소 | `A1:B2:C3:D4:E5:F6` → `•••` |

**가리지 못하는 것 — 반드시 알고 계셔야 합니다.**
사람 이름·대화방 제목·블루투스 기기 이름처럼 **정해진 형태가 없는 이름**은 위 규칙으로
찾아낼 수 없다. 형태가 없는 이름을 일반 규칙으로 지우려면 화면의 앱 이름까지 함께 지워야
하는데(앱 서랍의 앱 목록과 블루투스 기기 목록이 구조적으로 똑같다), 그러면 안내 자체가
성립하지 않는다. 그래서 **지우지 않기로 정했고, 그 이름들은 가려지지 않은 채 전송된다**
(`SPEC.md` §2 「패턴 밖 고유명」, 2026-08-22 결정).

입력칸도 같은 규칙을 쓴다. 검색어·메모·시간·수량처럼 위 패턴에 해당하지 않는 현재 값은
안내를 만들기 위해 서버와 인공지능 모델로 간다. 비밀번호 플래그가 있거나 입력칸의 이름·hint·
식별자에 PIN·OTP·인증 코드·보안 코드라고 표시된 값은 기기에서 제외하고 보내지 않는다.

대신 세운 방어선은 이렇다 — 배포용 앱에는 화면 상세 로그가 남지 않고(CI가 검사한다),
서버 운영 로그에는 화면 내용·목표·안내문을 남기지 않으며, 평가용 데이터로 옮길 때는
사람이 먼저 익명화한다. **다만 아래 3-5의 예외가 있다.**

### 3-2. 목표 문장 (필수)

「무엇을 하고 싶으신가요」에 입력하거나 말씀하신 문장, 그리고 되묻기에 답하신 내용.

- 음성은 **안드로이드 음성인식이 글자로 바꾼 결과만** 서버로 간다. 원시 오디오는 davi
  서버가 받지도 저장하지도 않는다(`AndroidManifest.xml` `RECORD_AUDIO` 주석, `SPEC.md` §4).
- 음성으로 말씀하신 문장에는 연락처 이름 같은 것이 들어갈 수 있어 **화면과 같은 가리기를
  적용하지 않는다** — 가리면 목표를 이해할 수 없기 때문이다. 그 문장은 서버와 인공지능
  모델로 전송되며, **앱·서버 운영 로그와 저장 파일에는 남기지 않는다**(다만 아래 3-5의
  예외가 있다 — 개발용 원본 저장은 요청을 통째로 남기므로 목표 문장도 함께 들어간다).
- 원시 오디오를 안드로이드 음성인식 제공자가 어떻게 처리하는지는 기기 제조사·구글의
  정책을 따른다. 가능한 기기에서는 기기 안에서 처리하는 인식을 우선한다.

### 3-3. 안내 이력 (필수)

한 번의 안내 세션 동안 보여드린 안내 최대 10개(안내 문장, 동작 종류, 대상 이름, 화면
요약, 화면이 바뀌었는지, 안내한 곳을 실제로 누르셨는지, §3-1의 화면 **내용** 지문, 그리고
서버가 만들어 돌려준 화면 **구조** 서명 — **이 서명에는 요소 이름과 창 제목이 들어가지
않는다**). 앱에서 유지하는 이력은 **메모리에만** 있고 세션이 끝나면 사라진다.
다비 서버는 이력을 저장하지 않는다(무상태). **다만 아래 3-5의 예외가 여기에도 걸린다** — 개발용 원본
저장은 요청을 통째로 남기므로 그 안에 이 이력도 함께 들어간다. 모델 요청에 실린 이력의
OpenAI 측 보관은 §6·§7을 따른다.

### 3-4. 계정 정보 (선택)

카카오 로그인을 하시면 카카오에서 받은 **회원번호**만 서버가 확인해 세션 토큰(JWT)을
만든다. **회원 데이터베이스를 두지 않는다** — 이름·이메일·프로필 사진을 받지 않고
저장하지도 않는다. 카카오 액세스 토큰은 검증에만 쓰고 로그·응답 어디에도 남기지 않는다
(`server/app/kakao_auth.py`).

세션 토큰은 기기의 앱 전용 저장소에 보관되며, 만료 시간이 지나면 무효가 된다.
**로그인 없이 시작하기**를 고르시면 이 항목은 아예 만들어지지 않는다.

### 3-5. 개발용 원본 저장 — 내부 도그푸딩 기기에 한함

**팀이 직접 쓰는 개발용 빌드에서만**, 그리고 그 기기가 서버 명단에 등록된 경우에만,
요청과 응답을 통째로 파일로 남긴다(`server/.dogfood-raw/`).

- 대상 기기는 **개발용 빌드에서 옵트인한 기기뿐이다.** 스토어에서 받으신 앱은 이 값을
  계산하지도 보내지도 않는다.
- 이 파일에는 **3-1에서 가리지 못한 이름이 그대로 남는다.**
- **자동 삭제가 없고 영구 보존이다**(2026-07-30 팀 합의). 이름이 그대로 남는다는 것을 알고
  다시 본 뒤에도 같은 결론이다(2026-08-25 재확인, #375). 열람 범위는 해당 컴퓨터의 소유자인
  팀원으로 제한하며, 원문을 저장소·이슈·PR에 붙이지 않는다.
- **클로즈드 베타 release 참여자는 이 저장 대상이 아니다.** release 앱은 원본 저장용 기기
  해시를 계산·전송하지 않으며, CI가 그 상수가 꺼져 있는지 검사한다.
- 이 항목은 **내부 도그푸딩 기기에만 걸리므로 외부 이용자에게 동의를 구하지 않는다** —
  앱의 「서비스 개선 기록」 동의 항목은 그래서 지금 화면에 뜨지 않는다. raw 저장 대상을
  넓히면 이 절과 §7·§8, 그리고 앱 동의 문구를 함께 고쳐야 한다(`SPEC.md` §3).

### 3-6. 운영 기록

요청 시각·응답 코드·처리 시간·모델 이름·무작위 요청 ID·화면 요소 개수·앱 버전,
**안내를 받으신 앱의 패키지명**(예: `com.kakao.talk`), 그 밖에 요청 종류별 개수·오류
종류 **같은** 비식별 값을 남긴다.
목표·화면 내용·안내문·음성 문장은 남기지 않는다(`server/CLAUDE.md` 운영 규칙).
무작위 요청 ID는 목표·화면·기기에서 만들어지지 않는다.

**패키지명이 남는다는 것은 「어느 앱을 언제 쓰셨는지」가 이 기록에 남는다는 뜻이다.**
화면에 무엇이 있었는지는 남지 않지만 앱 이름은 남는다. 보유 기간은 §7에 있다.

접속 IP 주소는 과도한 요청을 막는 데만 **서버 메모리에서** 쓰고, **어떤 로그에도 남기지
않는다**(`server/app/main.py` 레이트리밋 · `server/app/logging.json`의 access 로그 비활성 ·
`Dockerfile`의 `--no-access-log`). 이용자를 알아보거나 다른 기록과 잇는 데 쓰지 않는다.

## 4. 수집하지 않는 것

다음은 **코드가 그렇게 되어 있어서** 수집할 수 없다. **이 표는 「앱이 직접 가져오는가」의
축이다** — 같은 것이 화면에 보이면 3-1의 경로로 나간다. 두 축을 하나로 읽지 않으셔야 한다.

| 수집하지 않는 것 | 근거 |
|---|---|
| 사진·연락처·문자·통화기록·위치 | 앱이 해당 권한을 선언하지 않는다(`AndroidManifest.xml`은 인터넷·알림·마이크 셋뿐) |
| 녹음된 소리 파일 | 서버에 오디오를 받는 경로가 없다 |
| 비밀번호 칸과 인증·보안 코드라고 표시된 칸의 내용 | 비밀번호 상태나 입력칸 이름·hint·식별자의 일반 의미 표지를 확인해 값을 직렬화 전에 제외한다(#462) |
| 설치된 앱의 전체 목록 | 기기에서 찾은 패키지·이름·목록을 전송하지 않는다(#102·#128). **다만 앱 서랍 화면을 안내하면 거기 보이는 앱 이름은 3-1로 나간다** |

## 5. 이용 목적

수집한 정보는 **다음 한 걸음의 안내를 만드는 데만** 쓴다. 구체적으로 —
현재 화면과 목표를 인공지능 모델에 보내 다음 동작 하나를 정하고, 그 동작이 화면에 실제로
있는 근거를 갖는지 검증하고, 목표가 끝났는지 판정한다.

**광고·프로파일링·이용자 분석에 쓰지 않는다.** 판매하지 않는다.

| 받는 곳 | 무엇이 가는가 | 목적 |
|---|---|---|
| OpenAI (현재 release의 인공지능 모델 제공자) | 가리기를 거친 화면 정보, 목표 문장·구체화 대화와 답변, 안내 이력 | 목표 구체화·실행 앱 후보·다음 안내 한 걸음 생성 |
| 카카오 | 앱이 카카오에서 받은 액세스 토큰(검증 요청) | 로그인 확인 |
| 안드로이드 음성인식 제공자 (기기 제조사·구글) | 목표를 말씀하실 때의 **음성** | 말을 글자로 바꾸기 |
| Microsoft Azure (Container Apps · Log Analytics) | 서버가 처리하는 요청 전부가 그 위를 지나가고, §3-6의 운영 기록이 거기 쌓인다 | 서버 호스팅 |

**음성인식은 davi 서버를 거치지 않는다** — 기기의 안드로이드 음성인식이 직접 처리하고,
davi는 그 결과 글자만 받는다(§3-2). 기기 안에서 처리하는 인식이 가능하면 그쪽을 먼저 쓰고,
없으면 시스템 음성인식으로 넘어가며 그때 음성은 그 제공자의 정책에 따라 처리된다
(`SpeechRecognizerHelper.kt`). **davi 서버는 어느 경우에도 음성을 받지 않는다.**

**모델 제공자에게 가는 화면 정보에는 3-1에서 가리지 못한 이름이 포함된다.**
서버 코드는 다른 공급자도 지원하지만, 이 표의 현재 제공처는 release 설정 기준이다.
제공처를 바꾸면 이 표와 앱 고지·문서/동의 버전을 함께 갱신한다. 설정으로 바꿀 수 있다는
것만으로 다른 제공처에 대한 고지·동의가 완료되지는 않는다.

**OpenAI의 보관은 다비 서버의 미저장과 별개다.** 현재 서버는 Responses API를 사용하며
`store`를 지정하지 않는다(`server/app/llm_provider.py`). OpenAI 공식 정책상 이 경우 응답
데이터는 기본 최소 30일 보관된다. 요청·응답을 포함할 수 있는 악용 방지 로그는 별도로 기본
최대 30일 보관되며, 법적 의무나 서비스·제3자 보호상 필요하면 더 오래 보관될 수 있다.
API 데이터는 기본적으로 모델 학습에 사용되지 않지만 명시적으로 공유에 동의한 경우는 예외다.
이 배치에서는 조직·프로젝트의 공유 설정이나 Zero Data Retention 승인을 확인하지 않았으므로
무보관 적용을 주장하지 않는다. 근거: [OpenAI API 데이터 처리 안내](https://developers.openai.com/api/docs/guides/your-data)
(2026-08-31 확인).

그 밖의 제3자에게 제공하지 않는다. 법령에 따른 요구가 있는 경우에만 예외로 한다.

## 7. 보유 기간과 파기

| 항목 | 어디에 | 얼마나 |
|---|---|---|
| 화면 정보 | 다비 서버가 저장하지 않는다(무상태) | 요청 처리가 끝나면 사라진다. **단 어느 앱이었는지(패키지명)는 §3-6의 운영 기록에 남는다. OpenAI 측 보관은 아래 별도 행** |
| 모델 요청·응답 데이터 | OpenAI | Responses API 응답 데이터는 기본 최소 30일. 악용 방지 로그는 별도로 기본 최대 30일이며 법적·안전상 예외가 있다(§6). 조직별 무보관 설정을 적용한 것으로 간주하지 않는다 |
| 목표·안내 이력 | 앱 메모리 | 안내 세션이 끝나면 사라진다 (**3-5의 개발용 원본에는 함께 남는다**) |
| 동의 기록 | 기기의 앱 전용 저장소 | 앱을 삭제하면 함께 사라진다 |
| 세션 토큰 | 기기의 앱 전용 저장소 | 만료 시각까지. 로그아웃·앱 삭제로 사라진다 |
| 운영 기록(§3-6 — 앱 패키지명 포함) | 서버 | **이용자의 요청을 받는 운영 서버는 30일**(Azure Log Analytics). 팀이 개발용으로 따로 돌리는 서버의 로그는 7일이며, **스토어로 받으신 앱의 요청은 그쪽으로 가지 않는다**(`server/CLAUDE.md`) |
| 개발용 원본(3-5) | 팀 컴퓨터 | **영구 보존, 자동 삭제 없음** — 대상이 내부 도그푸딩 기기뿐이라는 전제로 그대로 두기로 했다(2026-08-25, #375). 클로즈드 베타 release 참여자는 이 저장 대상이 아니다. |

## 8. 이용자의 권리와 행사 방법

- **안내를 언제든 멈출 수 있습니다.** 안내창의 중지 버튼을 누르면 「안내를 그만 볼래요?」를
  한 번 되묻고, **○(그만)를 고르셔야** 그 세션의 화면 읽기가 끝난다. ×(계속)를 고르면 안내가
  이어진다 — **되묻기에 답하지 않으면 아직 끝난 것이 아니다.**
- **접근성 권한을 끄면 화면을 읽지 않습니다.** 안드로이드 설정 > 접근성 > 설치된 앱 >
  davi 에서 끌 수 있다. 권한이 꺼진 동안 davi는 어떤 화면도 읽을 수 없다.
- **동의를 철회하려면** 위와 같이 접근성 권한을 끄거나 앱을 삭제하시면 된다. 기기에 남은
  동의 기록과 세션 토큰은 앱 삭제와 함께 사라진다.
- **열람·삭제 요청**은 §1의 문의처로 하실 수 있다. 아래 개발용 원본 파일과 OpenAI에
  전송된 정보는 저장 위치와 확인·처리 경로가 다르므로 구분한다.
- **개발용 원본 파일** — 다비 서버는 일반 release 요청의 화면 원문을 저장하지 않는다.
  §3-5의 내부 도그푸딩 원본 파일은 요청하시면 해당 파일을 지운다.
  **그 원본은 대상이 내부 도그푸딩 기기뿐이므로, 해당 기기를 쓰는 팀원의 요청으로 처리한다** —
  기기를 가르는 값이 기기 안에서만 얻을 수 있는 해시라서다(`DogfoodDeviceId`). 클로즈드 베타
  release 참여자는 원본 저장 대상이 아니므로 이 파일의 열람·삭제 대상이 아니다. 외부 이용자
  원본 저장을 열려면 식별 경로부터 만들어야 한다 — raw 저장 대상을 넓힐 때의 선행 조건으로
  `SPEC.md` §3에 적어 두었다(#375).
- **OpenAI에 전송된 정보** — release 참여자도 §1로 문의할 수 있다. 제공자의 처리 절차와
  현재 식별 가능한 범위를 확인해 안내한다. 다비 앱에는 OpenAI 응답·악용 방지 로그를 조회하거나
  일괄 삭제하는 기능이 없으며, 개발용 원본 파일을 지우거나 앱을 삭제해도 제공자 측 자료가
  함께 삭제되는 것은 아니다. 제공자 측 보관·예외는 §6·§7을 따른다.

## 9. 안전성 확보 조치

- 화면의 정해진 형태를 가진 개인정보는 **기기 안에서** 먼저 바꾼다. 서버에서 바꾸면
  원본이 이미 기기를 떠난 뒤라 중간 경로에 남을 수 있기 때문이다.
- 서버가 같은 규칙으로 한 번 더 검사한다. 두 규칙의 정규식 본문이 같은지 CI가 검사한다.
- 앱에는 인공지능 모델의 API 키를 넣지 않는다. 키는 서버에만 있다.
- 배포용 앱에는 화면 상세 로그가 남지 않는다(CI 관문으로 고정).
- 배포용 앱은 개발용 원본 저장을 위한 기기 해시를 계산·전송하지 않는다. 이를 제어하는
  도그푸딩 옵트인 상수가 꺼져 있는지 CI가 생성된 release BuildConfig에서 확인한다(#455).
- 세션 토큰·카카오 액세스 토큰은 어떤 로그에도 남기지 않는다.
- 잠긴 화면에는 안내를 표시하지 않는다 — 화면이 꺼지면 표시를 걷고, 잠금이 풀린 뒤에만
  되살린다.

## 10. 접근성 서비스 사용 고지

davi는 안드로이드 **접근성 서비스**를 사용한다. 용도는 하나다 —
**현재 화면을 읽어 다음에 무엇을 누르면 되는지 화면 위에 표시하는 것.**

- **자동으로 대신 눌러 드리지 않는다.** 화면의 버튼은 사용자가 직접 누른다. 유일한 입력
  예외는 「바로 입력」이다 — 사용자가 안내창의 버튼을 직접 누르면 안내문에 적힌 입력값을
  해당 칸에 채운다. 검색 실행·전송은 대신하지 않는다(`SPEC.md` §2, #405).
- 화면 읽기는 **안내를 시작한 뒤에만** 일어난다.
- 읽은 내용은 위 5의 목적 외에 쓰지 않는다.

## 11. 만 14세 미만 아동

davi는 만 14세 미만 아동을 대상으로 하지 않으며, 아동의 개인정보를 의도적으로 수집하지
않는다.

## 12. 방침의 변경

수집 항목·이용 목적·제3자 제공처·보유 기간처럼 **동의의 전제가 바뀌면** 문서 버전과 앱의
`consent_version`을 함께 올려 다시 동의를 받는다. **v3(2026-08-31)**는 현재 release의
OpenAI 제공·보관과 Android 음성인식 제공자 처리를 명시하고, 앱 동의 문안도 함께 고친다.
개발용 raw 저장 대상은 넓히지 않고 서버의 공급자·저장 설정도 바꾸지 않는다.
v2에 동의한 이용자는 v3 앱으로 업데이트한 뒤 로그인 진입 흐름에서 다시 동의해야 한다.
게시 문서만 고쳐서는 기존 v2 APK의 재동의가 발생하지 않는다. 이 파일과 공개 게시본을
동기화하고 v3 앱의 재동의 흐름을 실기기로 확인한 뒤 배포 점검을 완료한다(`SPEC.md` §11).

### 부록 — 이 문서를 고칠 때

- 이 문서의 사실은 전부 코드·`SPEC.md`에 근거가 있다. **근거 없이 줄을 더하지 않는다.**
- 특히 §4 「수집하지 않는 것」은 하나가 거짓이 되면 나머지도 함께 신뢰를 잃는다. 코드가
  바뀌어 그 표의 한 줄이 거짓이 되면 **코드 PR에서 이 문서를 함께 고친다.**
- 앱 안의 동의 문안(`consent_*` 문자열)과 이 문서는 같은 사실을 말해야 한다. 한쪽만
  고치지 않는다.
- **원본과 게시본이 어긋나는 것을 지금은 사람만 막고 있다.** 이 저장소는 「두 자리가 같아야
  한다」를 대체로 CI 관문으로 고정해 왔는데(마스킹 정규식 대조 `check_masking_parity.py`,
  release 설정 `verifyReleaseConfiguration`) 이 문서만 규칙 세 줄이다. 게시본 대조를 CI로
  올리는 것은 부채로 적어 둔다(#371 리뷰).
