# SCREENS — 화면명세 (to-be)

2026-08-11 v1 초안. **구현 직전의 화면 계약이다** — 각 화면이 어떤 상태를 갖고 무슨
데이터를 보여주는지를 고정한다. 시각 원본은 Figma SSoT(Wireframe→Screens 파이프라인,
`DESIGN-CONVENTIONS.md`)이고, 이 문서는 동작·상태·데이터를 맡는다. 구현 확정의 장부는
이 문서가 아니라 **이슈**다 — 항목이 확정되는 순간은 이슈가 이 문서를 참조하며 열리는
순간이고, 방향이 바뀌면 `SPEC.md`가 먼저다.

상태 표기는 **[합의] / [제안] / [미결]** — 표기 없는
문장을 결정으로 읽지 말 것.

참조: `../SPEC.md`(범위) · `voice-goal.md`(음성 목표 계약) · `DESIGN-CONVENTIONS.md`
(토큰·컴포넌트·파이프라인) · davi-docs `PLAN.md`(장기 기획) ·
Figma SSoT https://www.figma.com/design/00Kt3AYBSBsb7zdAp9ypKi/SSoT

## ON-1 로그인 — 버킷 **Next(베타)**

- 목적: 카카오 계정으로 시작. 구성: 로고(`logo` 컴포넌트) · 앱명·태그라인 · `button/oauth-kakao`.
- **[합의] 이번 사이클 구현 대상이 아니다**(2026-08-11). 서버에 계정 개념이 없고 SPEC
  범위 밖. 디자인만 확보된 상태.
- [미결] 근거 기획 문서 부재 — PLAN.md에 로그인 카드가 없다. 베타 기획 시 "왜 로그인이
  필요한가"(가족 연동·개인화 등)부터 카드로 세운다.

## ON-2 권한 설정 — 버킷 Now

- 목적: 접근성·오버레이 권한 2종을 켜게 안내. 시니어 단독 수행 전제(단일 온보딩, SPEC §3).
- 구성: `card/guide`(icon=권한 일러스트, "앱 권한 설정 가이드" + 반복 애니메이션 안내) ·
  `button` secondary ×2(접근성 서비스 켜기 / 다른 앱 위에 그리기, showIcon).
- 상태: ① 미충족(기본) ② 충족(다음 단계로 자동 진행 — 와이어프레임 "권한 확인되면") ③
  권한 소실 복귀(업데이트 등 — 메인에서 이 화면으로).
- 데이터: 접근성 활성 여부(`AccessibilityManager` 대조), `Settings.canDrawOverlays()`.
  버튼 탭 → 시스템 설정 딥링크, 복귀 시 재확인(현 구현 경로 유지).
- [미결] 카드의 "반복 애니메이션" 실물 미정(현재 일러스트 슬롯만).
- 구현 연결: `MainActivity` 권한 경로(구현됨), 화면 분리·자동 진행은 신규.

## MA-1 홈 — 버킷 Now

- 목적: 음성 목표 입력의 진입점. "누르고 물어보세요" + `button/mic`(lg).
- 동작: mic 탭 → RECORD_AUDIO 런타임 권한 → `VoiceDialogueSession.start()` → MA-2
  (voice-goal ①②).
- 상태: 기본 / mic pressed. listening 상태 UI는 [미결](컴포넌트 variant 예약됨).
- 데이터: 없음(정적).

## MA-2 듣는 중 — 버킷 Now

- 목적: 발화 청취 상태 표시. "듣고 있어요" + 파형(브리딩) + `card/guide`(icon=false) +
  mic(sm — 컴포넌트 아님, 듣는 중 UI 확정 시 정리).
- 데이터: **부분 인식 결과를 카드에 실시간 표시**(voice-goal ② — `onPartialResult`).
- 상태: ① 듣는 중 ② [미결] 다시 듣는 중(#106 — NO_MATCH·TIMEOUT 재시도, 같은 대화 유지.
  화면 변형은 핑퐁 팀 와이어프레임 추가 대상) ③ [미결] 재시도 2회 초과 종료.
- 문구: 재시도·종료 안내 문구는 W8 범위 — 여기서 확정하지 않는다.

## MA-3 요청 구체화 (핑퐁) — 버킷 Now

- 목적: 서버 후속 질문 1개를 보여주고(TTS 병행) 재발화를 받는 루프의 시각 상태.
- 데이터: 서버 `message`(질문 — 동적, 서버 생성 문구), 직전 사용자 발화(말풍선,
  `color/surface/secondary` 배경).
- 동작: 질문 TTS 재생(SPEAKING) → 끝나면 자동으로 MA-2(LISTENING) 복귀 — 버튼 없음
  (voice-goal ⑧⑨).
- 상태: 질문 표시+재생 중. 최대 5왕복(10메시지) 초과 → **텍스트 입력 폴백** —
  [미결] **폴백 화면이 디자인에 없다**(2026-08-11). 핑퐁 팀 와이어프레임 추가 대상.
  임시 동작은 현 구현(기존 goalInput 복귀)을 따른다.

## MA-4 최종 확인 — 버킷 Now

- 목적: 확정된 goal 문장을 보여주고 시작 여부를 받는다. 음성+텍스트 동시(TTS 병행, 와이어프레임 결정).
- 구성: goal 문장(title 스타일) · `chip/confirm-pair`(lg: ×/○) · TTS 캡션.
- 동작: ○ → `GuideSession.start(goal)` → GD-1 (voice-goal ⑪⑫). × → MA-1 복귀(전체
  재시작 — 와이어프레임 확정).
- 데이터: 서버 `ready` 응답의 `goal`.
- 구현 연결: **현 구현(⑩ goalInput 채움 + 시작 탭)과 다르다** — 이 화면이 to-be이며
  전환은 구현 이슈로. [미결] 확인 발화("네/아니오")로도 응답 가능하게 할지(voice-goal
  §1 "음성 최종 확인" 없음과 연결).

## GD-1 화면 읽는 중 — 버킷 Now (오버레이)

- 목적: 세션 시작·화면 전환 직후 "지금 읽는 중"을 알린다.
- 구성: `overlay/frame-border`(tone=reading, 브리딩 모션) + `overlay/window`("화면을
  읽고 있어요").
- 데이터: 없음. 문구 확정은 W8과 함께 재검토 [미결].
- 구현 연결: 현 구현엔 이 상태의 시각 표시가 없다(WAIT/SEND 무표시) — 신규.

## GD-2 조작 안내 — 버킷 Now (오버레이)

- 목적: 다음 한 걸음 안내. 변형: ① 대상 있음 — `overlay/highlight`(kind=target) +
  안내창(instruction) ② 제스처/대상 없음 — 안내창만(하이라이트 kind 추가는 컴포넌트
  예약) ③ 정체 — 기존 안내 + 정체 접미사(현 구현 유지) ④ 미검증 done 상한 — 상한
  문구(현 구현 유지).
- 데이터: 서버 `instruction`(동적), 대상 bounds(하이라이트 위치·크기).
- 안내창 X 칩("그만 볼래요") 탭 → 세션 종료. **[미결] 오버레이 터치 계약** — 현
  오버레이는 `FLAG_NOT_TOUCHABLE`(표시 전용)이라 칩 터치가 불가능하다. 이 디자인은
  "터치 가능한 오버레이 중지 버튼"(SPEC §11 상한 안내 UX 재검토의 후보)을 채택하는
  **계약 변경**이며, 부분 터치 영역(칩만 받고 나머지 통과) 구현 검증이 선행돼야 한다.
  채택 시 재표시 기계 제거도 같이 본다(SPEC §11).

## GD-3 완료 확인 — 버킷 Now (오버레이)

- 목적: 목표 달성 판정 후 사용자 확인. 성공 오탐 대비가 목적이므로 **"미해결"만
  받는다**(새 질문은 새 세션 — 2026-08-04 결정).
- 구성: `overlay/frame-border`(tone=success) + 안내창("다 됐어요! 해결되셨나요?" +
  `chip/confirm-pair` sm: ×아직요/○됐어요).
- 동작: ○됐어요 → 세션 종료(MA-1 복귀). ×아직요 → 안내 계속(GD-2로, 같은 세션 유지).
- 데이터: 없음(고정 문구 — W8 재검토 [미결]).
- [미결] 오버레이 터치 계약 — GD-2와 동일.
- [미결] 현 완료 처리와의 관계 — 두 갈래다. ① **검증된 done의 자동 종료**
  (`DoneOutcome.STOP`, `verified=true` 경로)를 이 확인 단계로 대체할지. ② **미검증 done
  상한**(`DoneOutcome.LIMIT_REACHED`)은 "더 묻지 말고 사용자에게 확인을 넘긴다"라 이미
  이 화면과 목적이 같다 — GD-2 변형 ④(상한 문구)와 GD-3 중 **어느 화면이 상한을 받는지**
  정해야 한다. (#55는 "미검증 done을 종료 신호로 믿지 않는다"는 결정이고 ①의 근거가
  아니다 — `GuideSession.onDone` 주석 참고.)
