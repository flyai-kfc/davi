# SCREENS — 화면명세 (to-be)

2026-08-11 v1 초안. **구현 직전의 화면 계약이다** — 각 화면이 어떤 상태를 갖고 무슨
데이터를 보여주는지를 고정한다. 시각 원본은 Figma SSoT(Wireframe→Screens 파이프라인,
`DESIGN-CONVENTIONS.md`)이고, 이 문서는 동작·상태·데이터를 맡는다. 구현 확정의 장부는
이 문서가 아니라 **이슈**다 — 항목이 확정되는 순간은 이슈가 이 문서를 참조하며 열리는
순간이고, 방향이 바뀌면 `SPEC.md`가 먼저다.

상태 표기는 **[합의] / [제안] / [미결]**. **표기 없는 문장은 와이어프레임에서 파생된
[제안]이다** — 확정은 이슈가 이 문서를 참조하며 열리는 순간이다. 위의 "화면 계약"은
그 이슈가 무엇을 근거로 삼는지를 한자리에 모았다는 뜻이지, 이 문서 자체가 확정 장부라는
뜻이 아니다.

참조: `../SPEC.md`(범위) · `voice-goal.md`(음성 목표 계약) · `DESIGN-CONVENTIONS.md`
(토큰·컴포넌트·파이프라인) · davi-docs `PLAN.md`(장기 기획) ·
Figma SSoT https://www.figma.com/design/00Kt3AYBSBsb7zdAp9ypKi/SSoT

## 표면 구분

| 표면 | 화면 | 특성 |
|---|---|---|
| 앱 화면 | ON-*, MA-* | 일반 Activity UI (XML+ViewBinding) |
| 오버레이 | GD-* | 다른 앱 위에 그림. **표시 오버레이**(하이라이트 — 터치가 아래 앱으로 통과) + **조작 오버레이**(안내창·칩 — 터치를 받는다) 둘로 나뉜다(#126) |

제외: 사용법 가이드 화면(와이어프레임에서 보류/삭제), 텍스트 목표 입력 화면(`MainActivity` —
**개발 전용 백업으로 물러났다.** `src/debug/`에만 있고 런처에도 없어 `adb shell am start`로만
열린다, #123·#156).

음성 경로의 실패는 둘로 갈린다 — **인식 오류·무응답**은 MA-2 상태 ②(다시 듣는 중, [미결] #106),
**5왕복 초과**는 MA-3의 실패 화면([미결] #123에서 텍스트 폴백을 대체했다).

  · "로그인 없이 시작"(secondary).
- **[합의] 이번 사이클로 앞당긴다**(2026-08-16, 전원 구두 합의 — PLAN 로그인 카드로 문서화).
  2026-08-11의 "구현 대상 아님" 합의를 대체한다. 서버 계정 개념은 #165가 만들었다(무상태
  세션, SPEC §3).
- 동작 결정: **로그인은 필수 관문이 아니다** — 스킵이 항상 열려 있고(진행 중에도), 로그인
  실패·서버 장애가 앱 사용을 막지 않는다. 결정(세션 또는 스킵)이 있으면 화면 없이 통과한다.
- 상태: 최소 구현이 #166/#168로 진행 중(기존 토큰만 사용). Figma 디자인 확정 시 갈아입힌다.
- [미결] 시각 디자인 확정 — 현 구현은 기존 토큰 조합이다. **문구는 W8 범위가 아니다** —
  이 화면의 `login_*` 키는 #168이 함께 정한다(#29 전수 목록에서 제외).

## ON-2 권한 설정 — 버킷 Now

- 목적: 접근성·오버레이 권한 2종을 켜게 안내. 시니어 단독 수행 전제(단일 온보딩, SPEC §3).
- 구성: `card/guide`(icon=권한 일러스트, "앱 권한 설정 가이드" + 반복 애니메이션 안내) ·
  `button` secondary ×2(접근성 서비스 켜기 / 다른 앱 위에 그리기, showIcon).
- 상태: ① 미충족(기본) ② 충족(다음 단계로 자동 진행 — 와이어프레임 "권한 확인되면") ③
  권한 소실 복귀(업데이트 등 — 메인에서 이 화면으로).
- 데이터: 접근성 활성 여부(`AccessibilityManager` 대조), `Settings.canDrawOverlays()`.
  버튼 탭 → 시스템 설정 딥링크, 복귀 시 재확인(현 구현 경로 유지).
- [미결] 카드의 "반복 애니메이션" 실물 미정(현재 일러스트 슬롯만).
- 구현 연결: `OnboardingActivity`로 구현됨(#123). 권한 두 개가 갖춰지면 `ConversationActivity`로
  자동 진행하고, 밖에서 권한이 꺼지면 그쪽 `onResume`이 이 화면으로 되돌린다.
- **되돌리는 경로가 둘이다**(#190). 앱으로 돌아왔을 때 판정하는 위 경로에 더해, **안내 중 접근성이
  꺼지면 서비스가 스스로** 이 화면을 앞으로 가져온다(`ServiceOffAction.RETURN_TO_APP`). 사용자는
  설정 앱에 있으므로 오버레이로는 알릴 수 없고, 서비스가 띄운 토스트는 화면 전환에 삼켜진다(실측) —
  **왜 왔는지는 이 화면이 말한다**(`EXTRA_GUIDE_STOPPED` → `guide_service_off`).
  오버레이 권한까지 꺼져 있으면 복귀 자체가 막히므로(`BAL_ALLOW_SAW_PERMISSION` 면제 없음)
  그때만 서비스가 토스트로 알린다.

- 목적: 세션 시작·화면 전환 직후 "지금 읽는 중"을 알린다.
- 구성: `overlay/frame-border`(tone=reading, 브리딩 모션) + `overlay/window`("화면을
  읽고 있어요").
- 데이터: 없음. 문구 확정은 W8과 함께 재검토 [미결].
- 구현 연결: **테두리는 구현됨**(#127) — 세션 시작 직후·화면 흔들림·요청 전송·응답 대기를
  덮고 안내가 도착하면 꺼진다. 빠른 응답에서 깜빡이지 않게 짧은 지연 뒤에 뜬다.
  **안내창("화면을 읽고 있어요")은 아직 없다** — 문구가 [미결]이라 테두리만 넣었다.
  색·두께·주기는 Figma에 tone=reading 토큰이 없어 포인트 색 별칭을 쓴 임시치다.

## GD-2 조작 안내 — 버킷 Now (오버레이)

- 목적: 다음 한 걸음 안내. 변형: ① 대상 있음 — `overlay/highlight`(kind=target) +
  안내창(instruction) ② 제스처/대상 없음 — 안내창만(하이라이트 kind 추가는 컴포넌트
  예약) ③ 정체 — 기존 안내 + 정체 접미사(현 구현 유지) ④ 미검증 done 상한 — 상한
  문구(현 구현 유지).
- 데이터: 서버 `instruction`(동적), 대상 bounds(하이라이트 위치·크기).
- 안내창 X 칩("그만 볼래요") 탭 → 세션 종료. **[합의] 오버레이 터치 계약**(2026-08-13, #126) —
  안내창과 칩이 **조작 오버레이**에 함께 살고 그 창 전체가 터치를 받는다. 칩을 겨냥하다 빗나가도
  안내창이 흡수하므로, 가려서 보이지도 않는 아래 앱 버튼이 눌리지 않는다. 하이라이트는 표시
  오버레이에 남아 계속 통과한다. 칩의 **화면 안 위치는 아직 임시다** — Figma `overlay/window`가
  원본이고 확정되면 조정한다. 재표시 기계는 함께 걷지 않기로 했다(SPEC §11의 기각 근거 참조).

## GD-3 완료 확인 — 버킷 Now (오버레이)

- 목적: 목표 달성 판정 후 사용자 확인. 성공 오탐 대비가 목적이므로 **"미해결"만
  받는다**(새 질문은 새 세션 — 2026-08-04 결정).
- 구성: `overlay/frame-border`(tone=success) + 안내창("해결되셨나요?" +
  `chip/confirm-pair` sm: ×아직요/○됐어요).
- 동작: ○됐어요 → 세션 종료. **안내 대상 앱에 그대로 남는다**(다비 앱을 앞으로 가져오지
  않는다 — 방금 해낸 화면에 머무는 것이 "스스로 했다"는 경험에 맞다, 2026-08-14 결정).
  ×아직요 → 안내 계속(GD-2로, 같은 세션 유지).
- 데이터: 없음(고정 문구 — **W8에서 확정**, #29). 확신 있음/없음 두 갈래 모두 확인쌍을
  **화면 배치 순서대로**(×가 왼쪽, ○가 오른쪽) 부른다.
- [합의] 오버레이 터치 계약 — GD-2와 동일(#126이 조작 오버레이를 세웠다). 이 화면의 `chip/confirm-pair`는
  같은 창에 그대로 얹는다. 확인 중에는 중지 칩('그만 볼래요')을 숨긴다 — 컨트롤 행에는 한 번에
  하나만 앉는다.
- [합의] 현 완료 처리와의 관계 — **두 갈래를 이 한 화면으로 합치고 문구만 가른다**
  (2026-08-14 결정, #139). 검증된 done(`DoneOutcome.CONFIRM_CONFIDENT`)과 미검증 상한
  (`CONFIRM_UNSURE`)이 같은 화면을 쓰고, 사용자가 하는 일이 "끝났는지 답한다"로 같아
  ×아직요 처리 로직이 한 벌이면 된다. **`DoneOutcome.STOP`은 없앴다** — 세션 종료는
  사용자의 ○ 응답만이 만든다. (#55는 "미검증 done을 종료 신호로 믿지 않는다"는 결정이고
  검증된 done을 확인으로 돌린 근거는 아니다 — 그쪽은 성공 오탐 대비다.)
- [합의] ×아직요를 누른 화면에서 완료 신호가 상한까지 반복되면 확인 화면 대신 **안내창
  문구**(`NOTICE_ONLY`)로 떨어진다 — 같은 질문을 다시 하지 않으면서 재질의 총량도 묶는다.
