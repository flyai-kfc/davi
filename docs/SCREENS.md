# SCREENS — 화면명세 (to-be)

2026-08-11 v1 초안. **구현 직전의 화면 계약이다** — 각 화면이 어떤 상태를 갖고 무슨
데이터를 보여주는지를 고정한다. 시각 원본은 Figma SSoT(Wireframe→Screens 파이프라인,
`DESIGN-CONVENTIONS.md`)이고, 이 문서는 동작·상태·데이터를 맡는다. 구현 확정의 장부는
이 문서가 아니라 **이슈**다 — 항목이 확정되는 순간은 이슈가 이 문서를 참조하며 열리는
순간이고, 방향이 바뀌면 `SPEC.md`가 먼저다.

상태 표기는 **[합의] / [제안] / [미결]**. **표기 없는 문장은 와이어프레임에서 파생된
[제안]이다** — 확정은 이슈가 이 문서를 참조하며 열리는 순간이다. 위의 "화면 계약"은
그 이슈가 무엇을 근거로 삼는지를 한자리에 모았다는 뜻이지, 이 문서 자체가 확정 장부라는
뜻이 아니다.

참조: `../SPEC.md`(범위) · `voice-goal.md`(음성 목표 계약) · `DESIGN-CONVENTIONS.md`
(토큰·컴포넌트·파이프라인) · davi-docs `PLAN.md`(장기 기획) ·
Figma SSoT https://www.figma.com/design/00Kt3AYBSBsb7zdAp9ypKi/SSoT

## 표면 구분

| 표면 | 화면 | 특성 |
|---|---|---|
| 앱 화면 | ON-*, MA-* | 일반 Activity UI (XML+ViewBinding) |
| 오버레이 | GD-* | 다른 앱 위에 그림. **표시 오버레이**(하이라이트 — 터치가 아래 앱으로 통과) + **조작 오버레이**(안내창·칩 — 터치를 받는다) 둘로 나뉜다(#126) |

제외: 사용법 가이드 화면(와이어프레임에서 보류/삭제), 텍스트 목표 입력 화면(`MainActivity` —
**개발 전용 백업으로 물러났다.** `src/debug/`에만 있고 런처에도 없어 `adb shell am start`로만
열린다, #123·#156).

음성 경로의 실패는 둘로 갈린다 — **인식 오류·무응답**은 MA-2 상태 ②(다시 듣는 중, [미결] #106),
**5왕복 초과**는 MA-3의 실패 화면([미결] #123에서 텍스트 폴백을 대체했다).

## ON-2 권한 설정 — 버킷 Now

- 목적: 접근성·오버레이 권한 2종을 켜게 안내. 시니어 단독 수행 전제(단일 온보딩, SPEC §3).
- 구성: `card/guide`(icon=권한 일러스트, "앱 권한 설정 가이드" + 반복 애니메이션 안내) ·
  `button` secondary ×2(접근성 서비스 켜기 / 다른 앱 위에 그리기, showIcon).
- 상태: ① 미충족(기본) ② 충족(다음 단계로 자동 진행 — 와이어프레임 "권한 확인되면") ③
  권한 소실 복귀(업데이트 등 — 메인에서 이 화면으로).
- 데이터: 접근성 활성 여부(`AccessibilityManager` 대조), `Settings.canDrawOverlays()`.
  버튼 탭 → 시스템 설정 딥링크, 복귀 시 재확인(현 구현 경로 유지).
- [미결] 카드의 "반복 애니메이션" 실물 미정(현재 일러스트 슬롯만).
- 구현 연결: `OnboardingActivity`로 구현됨(#123). 권한 두 개가 갖춰지면 `ConversationActivity`로
  자동 진행하고, 밖에서 권한이 꺼지면 그쪽 `onResume`이 이 화면으로 되돌린다.
- **되돌리는 경로가 둘이다**(#190). 앱으로 돌아왔을 때 판정하는 위 경로에 더해, **안내 중 접근성이
  꺼지면 서비스가 스스로** 이 화면을 앞으로 가져온다(`ServiceOffAction.RETURN_TO_APP`). 사용자는
  설정 앱에 있는데, **서비스가 unbind되는 중이라 접근성 오버레이 창이 서비스와 함께 죽어
  안내창을 쓸 수 없다**(미검증 — 정리 순서상 그렇게 읽힌다). 화면이 설정 앱이라서가 아니다:
  접근성 오버레이는 설정 앱 위에도 그려진다(#56). 서비스가 띄운 토스트는 화면 전환에
  삼켜진다(실측) —
  **왜 왔는지는 이 화면이 말한다**(`EXTRA_GUIDE_STOPPED` → `guide_service_off`).
  오버레이 권한까지 꺼져 있으면 복귀 자체가 막히므로(백그라운드 activity 실행 금지의 면제가
  **둘 다** 그 권한에서 나온다 — `BAL_ALLOW_SAW_PERMISSION` · `BAL_ALLOW_NON_APP_VISIBLE_WINDOW`.
  **후자는 구 창 타입 기준 실측이고 #56 이후 인과가 끊겼다** — 결론은 전자만으로 선다)
  그때만 서비스가 토스트로 알린다. 이 복귀는 **온보딩을 task 루트로 만든다**(`CLEAR_TASK`) —
  살아 있는 `ConversationActivity` 위에 얹으면 되돌아올 때마다 대화 화면이 한 겹씩 쌓인다.

## MA-1 홈 — 버킷 Now

- 목적: 음성 목표 입력의 진입점.
- 구성(v2, #231): 2줄 제목(「어려운 건」 `#1A1A1A` / 「물어보세요」 `#F2001C`, Cafe24 Bold 34) +
  폭죽 + 부제「· 하나씩 알려드릴게요 ·」 + 지휘봉을 든 캐릭터(`ic_davi_cane`) +
  말풍선「무엇을 도와드릴까요?」 + `v2/button/mic` + 하단「· 눌러서 말하기 ·」.
  - **말풍선은 불투명이다**(`#FCF6F8` → `#FBF3F6`). 뒤에 캐릭터가 있어 유리 너머로 검은
    몸통이 비치면 회색 얼룩이 생긴다. 규칙: **카드·말풍선 뒤에 캐릭터가 있으면 불투명.**
    메인 8 카드가 같은 사정이다.
  - **폭죽은 글자가 아니라 화면 오른쪽 가장자리에 붙인다** — 제목이 가운데 정렬이라 글자의
    오른쪽 끝이 문구마다 달라진다. 시안 상자(60×57)가 아니라 **잉크 43×32**를 쓴다
    (`clipsContent = false`라 자식이 상자 밖으로 나가 있었다).
  - **마이크와 글로우가 이 화면에서만 위로 올라간다** — 아래에 캡션이 들어가기 때문이다.
    둘은 함께 움직여야 한다(글로우 여백이 마이크 기하에서 나온 값이다).
  - **실패 문구(`voice_no_speech`)는 말풍선이 받는다.** 따로 두면 마이크와 겹치고, 애초에
    "잘 듣지 못했어요"는 다비가 하는 말이라 말풍선이 제자리다.
- 이번 범위에서 뺀 것(#231, 디자인 담당 확인): **하단 파도** — 코드에 "파도는 사용자가
  말하는 동안에만 보인다"가 확정으로 있다(#132·#161). 홈에 상시 파도를 두면 파도가 "지금
  듣고 있다"는 신호를 잃는다. **왼쪽 위 햄버거** — 갈 곳(설정 화면)이 앱에 없다.
- 동작: mic 탭 → RECORD_AUDIO 런타임 권한 → `VoiceDialogueSession.start()` → MA-2
  (voice-goal ①②). **MA-2로 넘어가면 캐릭터·말풍선·제목이 함께 사라진다**(홈 전용 구성).
- 상태: 기본 / mic pressed. listening 상태 UI는 [미결](컴포넌트 variant 예약됨).
- 데이터: 없음(정적). 실패 문구만 직전 시도에서 온다.

## MA-5 실패 (메인 8) — 버킷 Now

- 목적: 목표를 정리하지 못했음을 알리고 처음으로 되돌린다.
- 구성: **전신 캐릭터**(`ic_davi_stand`) + 문구 카드 한 장. **배지·마이크·파도·버튼이 없다.**
- 문구: 「목표를 정리하지 못했어요 / 처음으로 돌아갈게요」 — Cafe24 19sp. 소관은 #29다.
  "응답"(시스템 용어)과 "무엇을 하려는지"(사용자를 탓하는 어감)를 피한 값이다.
- 동작: 버튼 없음. `FAILED_RETURN_DELAY_MS`(5초) 뒤 자동으로 MA-1 복귀.
- 데이터: 없음(고정 문구). `LimitReached`·`InvalidResponse`로만 들어온다.
- 배치: **이 화면만 구도가 다르다.** 캐릭터가 위를 차지하고 카드가 그 하단을 파고든다.

```
캐릭터  305x311dp  상단 61dp  가운데
카드    카드 폭 x 240dp  캐릭터 하단에서 53dp 겹침
```

  겹침은 캐릭터가 아니라 **카드의 음수 위 마진**이 만든다(배지와 같은 수법, 깊이만 36 -> 53dp).
  **절대 y로 옮기지 않는다** — 시안에서 이 화면 카드만 y266인데 다른 화면은 y108~134다.
- 이탈: **카드가 불투명이다.** 시안은 글라스인데 그대로 두면 캐릭터의 검은 몸통이 비친다
  (실기기: 겹침 구간이 회색 225로 떴다). 채움 값은 렌더된 픽셀에서 뽑아 배경 위에서는
  글라스와 같아 보인다. Figma 반영 대기(#208).
- 구현 연결: #208 / PR #220. 카드는 `state=speaking`이라 분홍 글로우가 켜진다 —
  실패 문구도 다비가 하는 말이다(#176).

## MA-4 최종 확인 — 버킷 Now

- 목적: 확정된 goal 문장을 보여주고 시작 여부를 받는다. 앱 실행 가능성을 확인하지 못한 경우에는
  앱을 고르는 대신 가능성 경고를 먼저 보여 주고, 계속하면 goal을 한 번 더 확인받는다(#185).
  음성+텍스트 동시(TTS 병행, 와이어프레임 결정).
- 구성: 기본은 goal 문장(title 스타일), 사전 확인 미확인은 "이 과정에 필요한 앱이 설치되어 있지 않을
  수 있어요. 그래도 계속할까요?" 문구 · **`v2/button/pair`(캡슐 ×/○)** · TTS 캡션.
- 동작: 확인됨은 ○ → `GuideSession.start(goal)` → GD-1 (voice-goal ⑪⑫). 미확인 경고의 ○ →
  원래 goal 최종 확인, 그 화면의 ○ → `GuideSession.start(goal)`. 어느 화면에서든 × → MA-1
  복귀(전체 재시작 — 와이어프레임 확정).
- **○의 글자가 화면마다 다르다**(#196): 경고는 "계속할래요", 최종 확인은 "네, 맞아요".
  확인 화면이 연달아 둘이라 같은 글자를 쓰면 "눌렀는데 또 물어본다"가 된다. #185가
  아이콘 전용 시절 `contentDescription`으로만 주던 구분을 **보이는 글자로 올린 것**이다.
- 데이터: 서버 `ready` 응답의 원래 `goal`, Android의 실행 가능성 사전 점검 결과(확인됨/미확인).
  후보 요청 API·HTTP·network·parse 실패도 원래 goal을 보존한 미확인이다.
- 배치: **버튼쌍이 카드 바로 아래(86dp)에 있고 화면 아래는 비운다**(#196). 마이크·시니어
  카드는 숨는다. PR #164가 마이크와 확인쌍을 한 바닥 슬롯에 묶었던 것을 뒤집은 결과다 —
  마이크 자리에 버튼이 앉으면 "눌러 말하세요"의 자리와 겹쳐 확인 화면이 입력 자리로 보인다.
- 구현 연결: 구현됨(#123·#185·#196). 앱 후보의 canonical name은 goal에 덧붙이지 않는다.
  **확인쌍은 오버레이(GD-3·4)와 별개 컴포넌트다** — 시안이 `v2/button/pair`(캡슐 흰/빨강)와
  `v2/confirm-pair`(r14 빨강/초록)로 나눠 두었다. 코드도 `view_davi_button_pair.xml`과
  `view_davi_confirm_pair.xml`로 갈라져 있고, 대화 화면은 앞의 것만 쓴다.
  [미결] 확인 발화("네/아니오")로도 응답 가능하게 할지(voice-goal §1 "음성 최종 확인" 없음과 연결).

## MA-6 안내 중 (메인 9) — 버킷 Now

- 목적: 안내를 받다가 **다비 앱으로 돌아온** 사용자에게 셋 중 무엇을 하려는지 묻는다 —
  기존 안내 계속 · 종료 · 새로 물어보기.
- 구성: 배지 + 카드(제목 "안내가 진행 중입니다" 20sp · 지시문 "새로 물어보시려면 / 먼저
  안내를 종료해주세요" 17sp) + **세로 버튼쌍** + 하단 안내("계속 보시려면 뒤로가기를 눌러 /
  다비를 나가주세요" 17sp). **마이크·파도·마이크 글로우가 없다.**
- 동작
  - **기존 안내 이어서하기** → 앱에서 나가기만 한다. **아무 상태도 바꾸지 않는다** — 안내는
    그대로 돈다. 하단 안내가 같은 동작을 뒤로가기로 설명하고, 버튼은 그걸 모르는 사람을 위한
    지름길이다.
  - **안내 종료** → MA-7 종료 확인.
  - 새로 물어보기는 버튼이 없다 — 마이크가 잠겨 있고 지시문이 "먼저 종료하세요"로 안내한다.
- 데이터: 없음(고정 문구).
- **[결정] "안내 중"은 화면 상태가 아니다**(#197). `GuideSession`이 들고 있는 바깥 사실이라
  화면 상태로 복제하면 세션이 밖에서 끝났을 때 화면만 남는다. 그릴 때마다 세션에 물어본다.
- 이탈: 버튼 높이가 시안 72dp **고정이 아니라 하한**이고, 간격 둘이 시안보다 좁다(버튼 사이
  35 → 24dp, 주 버튼 → 하단 안내 53 → 20dp). 배율 2.0에서 라벨과 하단 안내가 잘렸기 때문이다 —
  하단 안내는 "어떻게 안내로 돌아가는지" 알려주는 지시문이라 잘리면 사용자가 갇힌다.
  Figma 반영 대기.
- 구현 연결: #197 / PR #224. 임시 중지 버튼(`btn_stop_guide`)은 이 화면이 대신하며 지워졌다.

## MA-7 안내 종료 확인 (메인 10) — 버킷 Now

- 목적: 실수로 누른 종료를 되돌릴 자리. **MA-6 위에 모달로 덮인다** — 뒷화면이 그대로 보인다.
- 구성: 스크림 + 다이얼로그(확인 문구 Cafe24 Bold 18sp) + `chip/confirm-pair`(아이콘 전용).
  확인쌍은 오버레이(GD-3·4)와 **같은 컴포넌트**다 — 메인 7의 캡슐쌍과는 다르다.
- 동작: ✕ → MA-6 복귀(같은 세션). ○ → `GuideSession.stop()` 뒤 홈.
- **[결정] 자동 복귀 타이머가 없다** — 뒤에서 안내가 계속 돌고 있어 방치돼도 사용자가 갇히지
  않는다. MA-4 최종 확인과 다른 점이다.
- **[결정] 세션이 밖에서 끝나면 모달을 내린다**(#197 리뷰) — 끝낼 안내가 없는데 "정말
  종료할까요?"가 남으면 MA-6의 결정(유령 화면 금지)을 스스로 어긴다.
- 접근성: **확인쌍 설명을 이 화면 전용으로 덮는다.** 기본값이 최종 확인 기준이라 정반대다
  (✕가 "처음부터 다시", ○가 "이대로 안내 시작"). 모달 중에는 뒤 화면을 접근성 트리에서 빼고
  포커스를 문구로 옮긴다 — 스크림은 시각 차단일 뿐이다.
- 구현 연결: #197 / PR #224.

## GD-1 화면 읽는 중 — 버킷 Now (오버레이)

- 목적: 세션 시작·화면 전환 직후 "지금 읽는 중"을 알린다.
- 구성: `overlay/frame-border`(tone=reading, 브리딩 모션) + `overlay/window`("화면을
  읽고 있어요").
- 데이터: 없음. 문구 확정은 W8과 함께 재검토 [미결].
- 구현 연결: 테두리는 #127, **안내창은 #178**. 세션 시작 직후·화면 흔들림·요청 전송·응답
  대기를 덮고 안내가 도착하면 꺼진다. 빠른 응답에서 깜빡이지 않게 짧은 지연 뒤에 뜬다.
  안내창은 **첫 안내가 오기 전, 창이 비어 있을 때만** 뜬다 — 이미 안내가 떠 있는데 화면
  전환으로 읽는 중이 다시 켜져도 문구를 갈아 끼우지 않는다(보고 따라 하던 안내가 사라진다).
  문구 아래 점 셋은 대화 화면 "잠시만요"와 **같은 뷰·같은 리듬**이고 크기만 작다.
  색·두께·주기는 Figma에 tone=reading 토큰이 없어 포인트 색 별칭을 쓴 임시치다.

## GD-2 조작 안내 — 버킷 Now (오버레이)

- 목적: 다음 한 걸음 안내. 변형: ① 대상 있음 — `overlay/highlight`(kind=target) +
  안내창(instruction) ② 제스처/대상 없음 — 안내창만(하이라이트 kind 추가는 컴포넌트
  예약) ③ 정체 — 기존 안내 + 정체 접미사(현 구현 유지) ④ 미검증 done 상한 — 상한
  문구(현 구현 유지).
- 데이터: 서버 `instruction`(동적), 대상 bounds(하이라이트 위치·크기).
- 안내창 X 칩("그만 볼래요") 탭 → **GD-4 종료 확인**(#193). 여기서 곧바로 끝나지 않는다.
  **[합의] 오버레이 터치 계약**(2026-08-13, #126) —
  안내창과 칩이 **조작 오버레이**에 함께 살고 그 창 전체가 터치를 받는다. 칩을 겨냥하다 빗나가도
  안내창이 흡수하므로, 가려서 보이지도 않는 아래 앱 버튼이 눌리지 않는다. 하이라이트는 표시
  오버레이에 남아 계속 통과한다. 칩의 **화면 안 위치는 아직 임시다** — Figma `overlay/window`가
  원본이고 확정되면 조정한다. 재표시 기계는 함께 걷지 않기로 했다(SPEC §11의 기각 근거 참조).

## GD-3 완료 확인 — 버킷 Now (오버레이)

- 목적: 목표 달성 판정 후 사용자 확인. 성공 오탐 대비가 목적이므로 **"미해결"만
  받는다**(새 질문은 새 세션 — 2026-08-04 결정).
- 구성: `overlay/frame-border`(tone=success) + 안내창("해결되셨나요?" +
  `chip/confirm-pair` sm: ×아직요/○됐어요). v2 시안은 이 확인쌍에 버튼 라벨을 붙였지만
  **라벨은 쓰지 않기로 했다**(2026-08-18, 디자인 담당 결정) — 버튼에 글자를 얹는 대신
  **본문 둘째 줄이 무엇을 누르라는지 이른다**. 형식은 기호가 앞, 화면 배치 순서대로다
  (`× 아직, ○ 다 됐어요` / `× 계속, ○ 그만`). **GD-3와 GD-4가 같은 형식이다** — 같은
  컴포넌트를 두 화면이 다르게 설명하지 않는다. 뜻이 화면마다 다르므로
  `contentDescription`도 갈아 끼운다. 모양은 **높이 56 가로로 긴 캡슐**이다(시안 r14는 세로로 선 상자처럼 보였다).
- 동작: ○됐어요 → 세션 종료. **안내 대상 앱에 그대로 남는다**(다비 앱을 앞으로 가져오지
  않는다 — 방금 해낸 화면에 머무는 것이 "스스로 했다"는 경험에 맞다, 2026-08-14 결정).
  ×아직요 → 안내 계속(GD-2로, 같은 세션 유지).
- 데이터: 없음(고정 문구 — **W8에서 확정**, #29). 확신 있음/없음 두 갈래 모두 확인쌍을
  **화면 배치 순서대로**(×가 왼쪽, ○가 오른쪽) 부른다.
- [합의] 오버레이 터치 계약 — GD-2와 동일(#126이 조작 오버레이를 세웠다). 이 화면의 `chip/confirm-pair`는
  같은 창에 그대로 얹는다. 확인 중에는 중지 칩('그만 볼래요')을 숨긴다 — 컨트롤 행에는 한 번에
  하나만 앉는다.
- [합의] 현 완료 처리와의 관계 — **두 갈래를 이 한 화면으로 합치고 문구만 가른다**
  (2026-08-14 결정, #139). 검증된 done(`DoneOutcome.CONFIRM_CONFIDENT`)과 미검증 상한
  (`CONFIRM_UNSURE`)이 같은 화면을 쓰고, 사용자가 하는 일이 "끝났는지 답한다"로 같아
  ×아직요 처리 로직이 한 벌이면 된다. **`DoneOutcome.STOP`은 없앴다** — 세션 종료는
  사용자의 ○ 응답만이 만든다. (#55는 "미검증 done을 종료 신호로 믿지 않는다"는 결정이고
  검증된 done을 확인으로 돌린 근거는 아니다 — 그쪽은 성공 오탐 대비다.)
- [합의] ×아직요를 누른 화면에서 완료 신호가 상한까지 반복되면 확인 화면 대신 **안내창
  문구**(`NOTICE_ONLY`)로 떨어진다 — 같은 질문을 다시 하지 않으면서 재질의 총량도 묶는다.

## GD-4 종료 확인 — 버킷 Now (오버레이)

- 목적: 실수로 누른 종료를 되돌릴 자리. **종료 진입점을 ○ 응답 하나로 모은다** — #139가 검증된
  done까지 확인으로 돌린 뒤에도 X 칩만 즉시 종료로 남아 있었다.
- 구성: 스크림(전면) + 확인창(`v2/overlay/window-confirm`) + `chip/confirm-pair`
  (×아니요/○종료할래요). **화면 세로 중앙**이고 `frame-border`는 **없다** — 크롬이 GD-3와
  배타적이다(v2 시안).
- 동작: GD-2의 X 칩 → 이 화면. ○종료할래요 → 세션 종료(**안내 대상 앱에 그대로 남는다** —
  GD-3와 같다). ×아니요 → **직전 안내로 복귀**(같은 세션, 서버에 다시 묻지 않는다). 단 그
  사이 화면이 바뀌어 되살릴 안내가 없으면 폐기하고 그 화면을 다시 묻는다 — 옛 강조를 새 화면
  위에 그리지 않으면서 빈 오버레이도 남기지 않기 위해서다(#193).
- 데이터: 없음(고정 문구 — W8/#29 [미결]).
- [합의] 확인 화면 계약 — GD-3와 같다(#139). 화면에 소속되지 않으므로 재표시의 서명 폐기
  대상이 아니고, 사용자가 셰이드를 내리든 홈을 누르든 따라가며 ○/× 전에는 사라지지 않는다.
  **면제되는 것은 확인 화면 자신뿐이다** — ×로 *되살아나는* 것은 조작 안내라 서명 폐기 규칙을
  그대로 받는다(위 동작 줄). 이 구분이 GD-4에서 처음 생겼다: GD-3의 ×는 되살릴 것이 없다.
- [합의] **스크림은 시각 표시이고 터치를 막지 않는다.** 스크림을 그리는 표시 오버레이가
  `FLAG_NOT_TOUCHABLE`이고, 그 플래그를 뒤집는 것은 "안내만 하고 대신 조작하지 않는다"
  (SPEC §2)와 부딪친다. 막을 이유도 없다 — 이 화면은 ○/× 말고는 사라지지 않는다.
- [합의] GD-3와 **동시에 뜨지 않는다** — GD-3 표시 중에는 컨트롤 행이 확인쌍이라 X 칩이 없다.
  그래서 확인 상태를 겹쳐 쌓지 않고 종류 한 축으로 가른다.
- [미결] 라벨의 '종료' — 칩이 '그만 볼래요'인데 되묻기가 '종료'면 한 가지를 두 이름으로 부른다.
  #189가 세운 쉬운 말 원칙과도 어긋난다. #29/#178에서 함께 본다.
- [합의] **"중앙"의 기준은 시스템 바를 뺀 안전 영역**이다(#169). 안내창은 상태표시줄·내비게이션
  바에 걸치면 안 된다 — 안내창 사각형이 곧 조작 오버레이의 터치 영역이라 걸친 만큼 시스템
  버튼이 죽는다. 그래서 GD-4의 중앙도 화면이 아니라 그 안전 영역의 중앙이다.
- 구현 연결: 플로우·스크림·중앙 배치는 #193. 색·서체·간격·버튼 라벨은 #178.
  실측(2026-08-17 SM-S921N `dumpsys window`, 3버튼 내비) — 안전 영역 `[103, 2178]`, 확인창
  `[74,817-1006,1471]`으로 중심 1144다. 시안이 기준으로 삼는 화면 중심(1170)보다 **26px 위**.
  육안으로 중앙이고 시스템 바를 안 건드리므로 그대로 뒀다. 시안 수치 대조는 #178.
  **스크림은 상태표시줄을 안 덮는다** — 그리는 창이 `[0,103]`부터다. 전면으로 만들려면 창
  기하부터 바꿔야 해서 #178로 넘긴다. 창 타입 교체(#56) 후 재실측에서도 프레임은 그대로였다
  (`frame=[0,103][1080,2340]`, 2026-08-18) — 이 단언은 유효하다.
